# Known Selectors

Current best selectors for the FIREKaro signin page and the Google OAuth flow.
Read at Step 0 of the skill; proposed updates flow through
`self-update-protocol.md` Step N after user approval.

## FIREKaro Signin Page (`/auth/signin`)

| Element | Selector | Notes |
|---|---|---|
| "Continue with Google" button | `[data-testid="signin-google-button"]` | Set in `src/pages/auth/signin.vue:87`. Stable across Vuetify version bumps. |
| Hydration signal (literal) | text `"Continue with Google"` | Use with `mcp__playwright__browser_wait_for` + 10s timeout. |
| OAuth error alert | `.v-alert[type="error"]` (inside signin card) | Appears when URL query is `?error=oauth`. |
| Already-logged-in redirect trigger | `onMounted` hook in signin page | Calls `GET /api/auth/get-session` on mount — if authenticated, router pushes `/dashboard`. Do not rely on a button for this path; it is reactive. |

## FIREKaro Dashboard Landing

| Element | Selector | Notes |
|---|---|---|
| URL pattern (success) | starts with `http://localhost:5173/dashboard` | Accept `/dashboard` and any sub-route (see L-005 in learnings.md). |
| Session verification endpoint | `GET /api/auth/get-session` | Response `{ data: { user, session } }` on success; null or 401 on failure. Use `mcp__playwright__browser_network_requests` to confirm. |
| Dashboard top-level sections | 8 routes — `income`, `tax-planning`, `expenses`, `investments`, `liabilities`, `insurance`, `financial-health`, `fire-goals` | Any of these also counts as a successful landing. See `src/router/index.ts`. |

## Google OAuth Screens

Google's HTML is not stable and rewrites classes frequently. Do NOT hardcode
CSS selectors for Google elements. Use URL patterns and visible text instead.

| Screen | Detection Signal | Notes |
|---|---|---|
| Account picker | URL contains `accounts.google.com/o/oauth2/v2/auth` and visible text "Choose an account" | First screen users see. |
| Email/password form | URL contains `accounts.google.com/signin` and visible text "Enter your email" or "Enter your password" | User types directly — skill does NOT touch these fields (see `credential-protocol.md`). |
| 2-Step Verification | Visible text "2-Step Verification" or "Verify it's you" | User handles on phone. Record as observation only. |
| "This browser may not be secure" | Visible text of the same phrase | Critical failure — headless detection tripped. Abort and report. |
| Consent screen | URL contains `accounts.google.com/signin/oauth/consent` | First-time only. May add ~2s latency. |
| Device-trust / "Confirm it's you" | Visible text "Confirm it's you" | New observation — record via self-update if encountered. |
| Post-login redirect | URL matches `localhost:5173/**` | The skill's success signal; poll via `browser_wait_for` with 180s timeout. |

## Better Auth Internals (for context only — do NOT click through these)

| Element | Path | Notes |
|---|---|---|
| Social sign-in trigger | `/api/auth/sign-in/social` | Called by `authClient.signIn.social({ provider: 'google' })` in `src/lib/auth-client.ts`. Returns a 302 to Google. |
| OAuth callback | `/api/auth/callback/google` | Google redirects here after consent. Sets the session cookie and redirects to `callbackURL`. Must be registered in Google Cloud Console. |
| Session endpoint | `/api/auth/get-session` | Truth for "am I logged in". 200 + user on success. |
| Sign-out | `/api/auth/sign-out` | POST. Clears the session cookie. Not used by this skill. |

## Selector Drift Protocol

If a selector in this file no longer matches:

1. Do NOT fall back to a fragile heuristic (class name, position-based, text
   regex). Halt the run and ask the user whether the page has changed.
2. Capture a screenshot of the current page (with `credential-protocol.md`
   constraints — no credentials visible) and save to
   `.claude/skills/app-login/last-run.png`.
3. Queue a new CANDIDATE observation in Step 8 with:
   - **Type:** `gotcha` or `fix`
   - **Observation:** the old selector and what replaced it
   - **Application:** the new selector and how to detect future drift
   - **Supersedes:** the ID of the old entry, if any
4. Do NOT edit this file directly mid-run. Edits happen via
   `self-update-protocol.md` Step N.5 with user approval.
